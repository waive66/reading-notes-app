## 一、笔记背景修复

### 1.1 根因（不是样式问题，是链路问题）

排查后发现 **三个叠加缺陷**，只改按钮完全没用：

| # | 问题 | 证据 |
| --- | --- | --- |
| 1 | 背景图被白色遮罩盖住 | `.detail-bg::after` 的渐变是 `rgba(251,246,239,.86) → .96`，图片只剩 4%~14% 可见，等于没生效 |
| 2 | 背景只作用于"页面"，不作用于"纸面" | `.paper` 是纯白卡片（`background:#FFFFFF`），占屏 80%，改页面底色几乎看不出来 |
| 3 | 没有"颜色背景"这一能力 | 旧实现只能用相册照片，且存在独立的 `bg_n_<id>` 键，不在笔记数据里，无法按笔记管理 |

另外还发现一个**更严重**的隐藏 bug（见 1.4）。

### 1.2 修复方案

**数据模型**：背景并入每篇笔记的数据，成为一等字段：

```json
{ "v": 2, "html": "...", "text": "...",
  "bg": { "type": "none | color | image", "value": "#FBE9EC 或 file://路径" },
  "ai": { ... } }
```

**作用点**：颜色同时应用到
- 正文纸面 `.paper`（真正"笔记正文区域"）
- 页面底色（同色渐变到纸白，形成柔和过渡）

图片背景则铺在纸面上，并加一层 `rgba(255,253,249,.86)` 柔光保证文字可读；页面遮罩从 86~96% 降到 55~88%。

**预设**：默认纸白 / 温暖米黄 `#FBF1DF` / 浅粉 `#FBE9EC` / 浅蓝 `#E7F0F7` / 浅绿 `#E8F2E9` / 浅紫 `#F0EAF6` / 燕麦 `#F3EADC` / 薄荷 `#E6F3F1`，外加「用照片做背景」。

**交互**：顶部 🎨 打开面板 → 点色块**立即生效**（同时写盘）→ 面板不关闭，可连续预览。

### 1.3 数据迁移（旧数据不丢）

- 旧版把背景图存在独立键 `bg_n_<id>`；读取时若笔记里没有 `bg` 字段，会自动把该图并入 `note.bg = {type:'image', value}`，**原图不删、不动**。
- 旧版纯 HTML 日记（`n_<id>` 直接是 HTML 字符串）继续按 v2 兼容读取，`bg` 缺省为 `none`。
- 没有任何破坏性写入；`localStorage` 旧键全部保留。

### 1.4 顺带修掉的两个 bug

1. **重开日记正文不渲染**（严重）
   原实现用 `setTimeout(…,0)` 往编辑器写 `innerHTML`，但此时 ref 可能还没挂上 → 正文空白、字数却显示正常。
   改为 `useEffect([loading])` + `hydrated` 标记，**只在编辑器真正挂载后灌一次内容**。
   实测：刷新页面 → 重新进入 → 正文与图片都在（见 `docs/screenshots/09`）。

2. **冷启动深链接失效**
   `ProtectedRoute` 在登录态尚未从 localStorage 恢复时就判定"未登录"并跳转，导致直接打开某篇日记会落回首页。
   改为 `if (auth.loading) return null`，等恢复完再判断。

## 二、AI 服务商管理

### 2.1 两级设置，严格分开

| 层级 | 位置 | 管什么 |
| --- | --- | --- |
| **全局 AI 服务设置** | 首页 ⚙ → 设置 → AI 服务设置 | 服务商、模型、API Key、Base URL、调用方式 |
| **单篇日记 AI 设置** | 日记页底部 AI 卡片 | 这篇是否开启 AI、整篇分析 / 实时陪伴 |

两者互不影响：换服务商不会改变任何日记的开关；关掉某篇日记的 AI 也不会动全局配置。

### 2.2 Provider Adapter（不是同一套 body 硬套）

`client/src/ai/providers.js`：

| 服务商 | kind | 请求形态 |
| --- | --- | --- |
| OpenRouter | `openai` | `POST {base}/chat/completions`，Bearer 鉴权，附带 HTTP-Referer |
| DeepSeek | `openai` | 同上，`https://api.deepseek.com/v1` |
| 自定义 | `openai` | 同上，只支持 OpenAI 兼容接口 |
| Google Gemini | `gemini` | `POST {base}/models/{model}:generateContent?key=…`，body 用 `systemInstruction` + `contents`，**完全不同的结构** |

响应取文本也分开实现（`choices[0].message.content` vs `candidates[0].content.parts[]`）。

### 2.3 默认模型

- 默认服务商 **OpenRouter**，默认模型 **`openrouter/free`**。
- `openrouter/free` 是 OpenRouter 的 **Free Models Router**（自动挑选一个免费模型），官方 FAQ 明确列出，**不是一个具体模型，因此不出现在 `/api/v1/models` 列表里**——这一点最初判断错了，已更正。
- 其余内置可选（`/api/v1/models` 中实测 `pricing.prompt/completion` 均为 0 的 `:free` 模型）：`baidu/ernie-5.5-flash-preview:free`、`inclusionai/ling-3.2-flash:free`、`thinkingmachines/inkling-2-small:free`、`nvidia/nemotron-3.5-super-vl:free`、`particle-ai/particle-1:free`、`recursive/flint-v1.0:free`、`liquid/lfm-3-1.7b:free`。

### 2.3.1 「免费」到底免费到什么程度（官方文档口径）

| 项 | 事实 |
| --- | --- |
| 创建 API Key | 免费，不收费 |
| `:free` 模型推理 | `pricing.prompt` / `pricing.completion` 均为 0，不扣 credits |
| 速率限制 | 累计购买 credits < 10：**20 次/分钟、50 次/天**；≥ 10 credits：20 次/分钟、**1000 次/天** |
| 余额影响 | 账户余额为负时，**连免费模型也可能报错** |
| 持久性 | 免费模型可能下架或改价，不作长期可用承诺 |
| 数据 | 默认不记录 prompt/completion；会记录或无法确认策略的服务商，只有在用户主动打开日志/训练开关时才会被路由 |

来源：<https://openrouter.ai/docs/faq>、<https://openrouter.ai/docs/api_reference/limits>（2026-11-16 读取）。

### 2.4 两种调用方式

| 方式 | 密钥位置 | 说明 |
| --- | --- | --- |
| **后端代理（默认）** | 只在服务端环境变量 | APK 里没有任何 Key；客户端只 POST 到你的 `/api/ai/analyze` |
| **自带密钥直连** | 手机本地（Android Keystore 加密） | 手机直接请求服务商；界面上明确提示"客户端密钥存在被逆向提取的风险" |

服务端 `server/routes/ai.js` 已支持三家：

```
OPENROUTER_API_KEY / GEMINI_API_KEY / DEEPSEEK_API_KEY
```

各用各的变量，**不会把一家服务商的 Key 当成另一家的**。OpenRouter 非 `:free` 模型默认被服务端 403 拒绝（`ALLOW_PAID_MODELS=false`）。

### 2.5 密钥安全

- **APK 内不含任何开发者密钥**（构建产物里搜不到 `sk-` / `AIza`）。
- 原生新增 `SecretStore` 桥：Android Keystore 生成不可导出的 AES-256 密钥 → `AES/GCM/NoPadding` 加密 → IV+密文存 SharedPreferences。明文只在加密那一刻存在于内存，**不写日志**。
- 浏览器调试环境无 Keystore 时退化到 localStorage，并在界面上明确标注"未加密，仅限调试"。
- 界面默认掩码 `sk-o••••••••1234`，需点「显示」才展开。

### 2.6 费用控制

1. 只有 `openrouter` 且模型以 `:free` 结尾 → 判定为**明确免费**，可直接调用。
2. 其余一切（非 `:free` 的 OpenRouter 模型、Gemini、DeepSeek、自定义）→ 必须在设置页勾选「我已知悉该模型可能产生费用」后，`paidAck` 才会写入，否则调用直接被客户端拦下并提示。
3. 不自动切换模型、不自动充值。
4. 实时陪伴仍保留 6 秒防抖 + 15 秒最小调用间隔；服务端另有每 IP 每分钟 10 次 / 每天 200 次限流。

### 2.7 连接测试

- 使用固定文本「请只回复两个字：收到」，**绝不发送任何日记内容**。
- 校验链路：地址可达 → 鉴权 → 模型存在 → 返回非空 → 是否包含中文。
- 失败原因映射：`401/403` 密钥无效、`402` 额度不足、`404` 地址或模型不存在、`429` 限流、`5xx` 服务端异常、超时/网络异常分别提示。
- **只有测试通过才允许保存为当前服务**；测试失败时旧配置保持不变。
- 「拉取模型」按钮：Gemini 走 `/models?key=`，OpenAI 兼容走 `/models`，避免写死过期型号。

## 三、桌面图标

### 3.1 设计

奶油白径向渐变底（`#FFF9F0 → #F6E2C6`）＋ 陶土色封面（`#D6946E`）的打开日记本，右页一枚柔粉色小爱心（`#E28C7E`），左侧两枚金色光点（`#E8BE78`）；圆润无棱角、无文字、无书架/阅读器元素。

预览：`docs/icon-preview.png`（方形 / 圆形 / 自适应前景三态）。

### 3.2 真正替换（不是只放图片）

原来 `AndroidManifest.xml` **根本没有 `android:icon` 属性**，只有一张 124~548 字节的占位图。本次：

| 项 | 处理 |
| --- | --- |
| Manifest | 新增 `android:icon="@mipmap/ic_launcher"`、`android:roundIcon="@mipmap/ic_launcher_round"` |
| 传统图标（< API 26） | mdpi 48 / hdpi 72 / xhdpi 96 / xxhdpi 144 / xxxhdpi 192，方形 + 圆形各一套 |
| 自适应图标（API 26+） | `mipmap-anydpi-v26/ic_launcher(.xml/_round.xml)`：背景 + 前景分层 |
| 前景安全区 | 主体控制在画布中心 66% 内（108dp 中的 72dp 安全区），不会被圆形/方形裁切 |
| Android 13 主题图标 | 新增 `<monochrome>`，并输出各密度 `ic_launcher_monochrome.png` |

### 3.3 验证

`aapt2 dump badging` 输出：

```
application: label='心笺' icon='res/mipmap-anydpi-v26/ic_launcher.xml'
application-icon-160/240/320/480/640/65534: 'res/mipmap-anydpi-v26/ic_launcher.xml'
```

APK 内已包含全部 22 个图标资源（5 密度 × 方形/圆形/前景/单色 + 自适应 XML）。

## 六、需要你补充的配置

1. **OpenRouter Key**（要真实调用的话）：<https://openrouter.ai/keys>，填到服务端 `.env` 的 `OPENROUTER_API_KEY`，或 App 内切「自带密钥」填进去。
2. **Gemini / DeepSeek Key**（如要使用）：填 `GEMINI_API_KEY` / `DEEPSEEK_API_KEY`。
3. 服务端跑起来后，在 App「设置 → 调用方式 → 后端代理地址」填 `http://你的电脑IP:3001`（手机与电脑同一局域网）。
