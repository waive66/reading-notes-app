## 0. 先看清楚这个项目的真实形态

你提到的"Kotlin 还是 Java / XML 还是 Compose"——**本项目都不是原生 Android 界面**。

| 项 | 实际情况 |
| --- | --- |
| 语言 | JavaScript（React 18）+ Java（仅容器层一个 `MainActivity`） |
| UI | React 单页应用，运行在 Android **WebView** 里；样式为手写 CSS，**不是 XML，也不是 Compose** |
| 容器 | `android-for-apk/.../MainActivity.java` 加载 `file:///android_asset/public/index.html` |
| 数据 | 浏览器 **localStorage**（无 Room / SQLite / Postgres 参与客户端） |
| 网络 | 客户端原本零请求；本次新增 AI 时才引入 `fetch`，且只指向自建后端代理 |
| 编译 | 前端 `vite build` ✅ 通过；**Android APK 未能编译**（本机无 Android SDK，见第 9 节） |

所以本次升级分两层：**React 前端**（首页、图文、AI 界面与逻辑）+ **Java 容器**（图片存储桥、状态栏配色、应用名）。

## 3. 图文混排

### 3.1 插入
工具栏「🖼」按钮 → `<input type="file" accept="image/*">` → WebView 的 `onShowFileChooser` 拉起系统选择器（**不需要存储权限**，Manifest 未申请 READ_EXTERNAL_STORAGE）。
选图后在**当前光标处**插入，随后光标自动落在图片下方的空段落，可以继续写。

### 3.2 结构
```html
<div class="doc-figure" contenteditable="false" data-img="img_1750000000_ab12.jpg">
  <img src="file:///data/user/0/com.readingnotes.app/files/diary_images/img_....jpg">
  <button class="img-del" contenteditable="false">删除图片</button>
</div>
```
- `contenteditable="false"` 让图片整体作为一个不可分割的块，避免文字插入图片内部；
- `data-img` 记录文件名，删除时可同步清理磁盘文件；
- 图片与前后文字**共用同一个 HTML 流**，因此顺序天然保持，删除图片只移除该 `<div>`，不影响其他文字。

### 3.3 持久化（关键）
| 场景 | 处理 |
| --- | --- |
| 有原生桥（APK） | 图片压缩为 JPEG（最长边 1280，q0.78）→ base64 传给 `ImageStorage.saveImage()` → 写入 `getFilesDir()/diary_images/` → 返回 `file://` 路径存进 HTML |
| 无原生桥（浏览器调试） | 回退为 dataURL 直接内联（会占用 localStorage，仅用于调试） |
| 重新打开日记 | HTML 中的 `file://` 路径直接可用；App 私有目录路径在重启后不变 |
| 删除图片 | 移除节点 + 调用 `ImageStorage.deleteImage(name)` 删文件 |

这样做的好处：**图片不占 localStorage 配额**（旧版把背景图 dataURL 塞进 localStorage，5MB 很快爆掉）。

原生桥接口（`MainActivity.java`）：
```java
@JavascriptInterface String saveImage(String name, String dataUrl);  // 返回 file:// 路径
@JavascriptInterface String getImagePath(String name);
@JavascriptInterface boolean deleteImage(String name);
@JavascriptInterface long usedBytes();
```

## 5. AI 情感陪伴（每篇日记独立）

### 5.1 数据模型
每篇日记的 AI 状态存在自己的笔记 JSON 里，互不影响：

```json
{
  "v": 2,
  "html": "<div>…</div>",
  "text": "纯文本快照",
  "updatedAt": "2026-11-16T08:30:00.000Z",
  "ai": {
    "enabled": false,
    "mode": "whole",              // whole = 整篇分析, live = 实时陪伴
    "consentAt": null,            // 首次同意时间
    "live": {
      "active": false,
      "startedAt": null,
      "analyzed": [ {"h":"h1abc","t":"","at":"…"} ]   // 已消化的段落（基线也在这里）
    },
    "responses": [ { "id":"r_…", "mode":"whole", "primary":"失落", "secondary":["疲惫"],
                     "understanding":"…", "reply":"…", "suggestion":"…",
                     "crisis":false, "mock":false, "at":"…" } ]
  }
}
```

**旧日记兼容**：`n_<id>` 若仍是纯 HTML 字符串，读取时自动识别为 v2 的 `html` 字段，内容与样式原样保留（见截图 07）。

### 5.2 开关与同意
- 默认**关闭**；关闭状态下 `aiClient` 直接拒绝发送（`if (!ai.enabled) return`）。
- 首次开启弹出说明：会发送**这篇日记中选择分析的文字**、会生成回应、**图片不发送**、可随时关闭、AI 不构成诊断。点「同意并开启」才写入 `consentAt`。
- 没有任何全局开关；A/B/C 三篇日记各管自己。

### 5.3 模式一：AI 整篇分析
点击「分析整篇笔记」→ 取编辑器当前全文（`htmlToText`，图片替换为 `[图片]` 占位）→ 调 `analyze()` → 结果卡片展示：主要情绪、辅助情绪、AI 的理解、针对经历的回应、建议。
修改后可再次点击覆盖/追加（保留最近 30 条）。

### 5.4 模式二：AI 实时陪伴（重点）
```
点击「开始实时陪伴」
  → 把当前所有段落做哈希，写入 analyzed（baseline，标记为已消化，不上传）
  → 之后每次输入：6 秒防抖 → extractFresh()
      · 逐段哈希，已存在 analyzed 的跳过
      · 新增段落 → 送分析
      · 被修改的段落哈希变了 → 视为新内容 → 送分析
      · 删除段落 → 自然消失，不触发
  → 单次最多 1000 字；两次调用最小间隔 15 秒（不足则顺延并提示）
  → 成功后把本次段落哈希写回 analyzed，避免重复上传
  → 也可点「立即分析新内容」手动触发
```
- 重开日记**不会**重跑：`analyzed` 随笔记持久化。
- **不会**因为开启实时陪伴就把整篇历史上传：开启瞬间只做基线标记。
- 失败不写入 `analyzed`，可重试。

### 5.5 回应风格
提示词写在服务端 `server/routes/ai.js` 的 `SYSTEM_PROMPT`，明确要求：先理解感受、针对具体事件、不否定情绪、不强迫乐观、不说教、不做诊断；出现自伤/自杀等信号时 `crisis=true` 并在界面显示求助提示（含 12356 心理援助热线）。
每条回应底部固定标注「AI 生成内容，仅供参考，不构成任何诊断或医疗建议」。

## 7. 隐私

1. **默认不联网**：不开启 AI 时，客户端不发出任何请求（`fetch` 只在 `aiClient.analyze` 里）。
2. **只发文字**：`htmlToText` 把 `<img>` 替换成 `[图片]` 占位符，模型**收不到任何图片**。
3. **只发授权内容**：未开启该日记的 AI 时直接 return；实时模式只发增量段落。
4. **密钥不落地客户端**：APK 里没有任何 API Key，密钥只在服务端环境变量。
5. **服务端不持久化**：`routes/ai.js` 只做转发，不写库、不落盘；日志不打印正文。
6. **测试用虚构内容**：验收截图里的日记均为演示数据，未使用真实私人日记。

## 8. 构建与两个关键修复

### 构建
```bash
cd client && node node_modules/vite/bin/vite.js build
# 产物：dist/index.html + assets/app.js + assets/style.css
# 复制到 android-for-apk/app/src/main/assets/public/  （本次已同步）
```
当前产物：`app.js 196.96 KB（gzip 65.05 KB）`、`style.css 17.03 KB`，43 个模块。

### 修复 1：file:// 下白屏（致命）
Vite 默认注入 `<script type="module">`，WebView 以 `file://` 加载时会被 CORS 拒绝执行 → **整个 App 白屏**。
`vite.config.js` 新增 `classicScriptTag` 插件改写为普通脚本。

### 修复 2：脚本时序（同样致命）
去掉 `type="module"` 后脚本变成阻塞式，在 `<head>` 中立即执行时 `#root` 还没解析，`createRoot(null)` 抛错 → 仍然白屏。
插件最终输出 `<script defer src=...>`，并把样式表的 `crossorigin` 去掉（同为 file:// 限制）。
已验证：用 `--allow-file-access-from-files` 打开 `assets/public/index.html`，`#root` 内正常渲染出登录页。

> 这两个问题在浏览器 / HTTP 调试下**完全看不出来**，只有真机 file:// 才暴露。如果你之前直接拿旧 `dist` 打包，很可能就是白屏。

## 10. 已知限制

1. 富文本用 `span` 包裹，复杂选区（跨多个块）可能产生嵌套样式，属已知取舍。
2. 实时陪伴按**段落**做增量：在旧段落中间改一个字，整段会被重发（可接受，但会产生一次额外调用）。
3. 图片只做了压缩，没有做 EXIF 清理；如需极致隐私可再加。
4. 免费模型输出 JSON 的稳定性不如付费模型，解析失败会返回「模型返回格式无法解析」，可换模型重试。
5. 未做多端同步；数据仍在本机（这是当前设计，不是缺陷）。
